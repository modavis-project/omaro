# Multidimensional comparison example

This synthetic fixture shows why an organological classification cannot be
reduced to one universal tree or one unqualified similarity score. The same
three configured targets are compared twice. A morphology-focused profile
makes the tambourine configuration identical to the frame-drum configuration
on the selected variables. A performed-sounding profile instead makes it
identical to the jingle-ring configuration. No target changes identity, and no
analysis is declared uniquely correct.

The method follows the non-hierarchical, multidimensional comparison proposed
by René T. A. Lysloff and Jim Matson in [“A New Approach to the Classification
of Sound-Producing Instruments”](https://doi.org/10.2307/852139). It is an
illustrative adaptation, not a transcription of their dataset and not a claim
of conformance to a named analytical school.

All targets, observations, procedures, perspectives, scopes, and results use
the `example.org` domain and are synthetic. They describe no collection
object, performance, person, or community.

## What the file contains

[`scalogram.json`](scalogram.json) records:

- three stable target URIs;
- six explicitly defined binary dimensions;
- one status-qualified assessment per target and dimension;
- two analysis profiles that select different dimensions without changing the
  underlying assessments;
- the declared distance rule and missing-value policy;
- pairwise distances; and
- the nearest target to the tambourine under each profile.

The morphology profile selects membrane presence, frame-membrane construction,
and a single tightly stretched membrane. It yields:

| Pair | Normalized distance |
|---|---:|
| tambourine ↔ frame drum | 0.0 |
| tambourine ↔ jingle ring | 1.0 |

The performed-sounding profile selects sounding attached rattlers, indirect
shaking, and a cluster-or-noise intention. It yields:

| Pair | Normalized distance |
|---|---:|
| tambourine ↔ frame drum | 1.0 |
| tambourine ↔ jingle ring | 0.0 |

The conclusion is methodological: similarity is relative to a declared
research question, variable set, procedure, perspective, scope, and comparison
rule. A distance of zero means only that two rows agree on the selected
variables. It does not assert physical identity, `owl:sameAs`, taxonomic
equivalence, cultural equivalence, or permission to publish.

## Status handling

Each cell preserves an assessment status. `detected` maps to binary value `1`
and `not-detected` maps to `0` only because the fixture declares a completed
binary detection procedure. `indeterminate`, `not-observed`, and
`not-applicable` map to `null`; they are excluded pairwise and reported. They
must never be silently converted to zero. A comparison fails rather than
returning a distance if fewer than the profile's declared minimum number of
dimensions remain comparable.

## Modeling the method in OMARO

The fixture is an analytical exchange example, not a new normative OMARO
record type. Its parts map to the ontology as follows:

| Analytical element | OMARO representation |
|---|---|
| stable row subject | `OrganologicalTarget` |
| variable definition | `ClassificationCriterion` with property, procedure, perspective, scope, and evidence |
| cell value | `ObservationAssessment`; an actual attempt additionally projects as `OrganologicalObservation` |
| selected variable set and distance rule | a versioned external analytical method or protocol resource |
| category conclusion, if one is made | `ClassificationAssertion` generated by a `ClassificationAssignment` that names its criteria, assessments, method, perspective, and scope |
| scalogram or distance result | an external analytical result used as evidence; OMARO does not recast proximity as identity |

OMARO deliberately does not provide a universal weighting scheme or infer a
Hornbostel–Sachs class from distance. An implementation may reproduce the
calculation from this file, but any classification conclusion still requires a
governed criterion and an explicit assignment. A culturally situated variable
also requires the relevant authority, protocol, applicability, and use
decision; an analytical purpose does not grant permission.

## Recalculation

For each profile and target pair:

1. take only the dimensions named by the profile;
2. translate `detected` to `1`, `not-detected` to `0`, and the three unresolved
   statuses to `null`;
3. retain dimensions on which both targets have a non-null value;
4. count disagreements;
5. divide disagreements by the number of comparable dimensions; and
6. report both the distance and the excluded dimensions.

The repository test suite recalculates every published comparison, checks the
two contrasting nearest-neighbour results, and rejects silent treatment of an
unresolved status as absence.
